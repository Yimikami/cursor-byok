## Native model-picker repair

The initial genuine free-account session reverted to Auto after account metadata
settled. A saved Letum label was not evidence of a working selector. The separate
PR #16 companion was excluded at the user's request.

The current native client exempts its existing own-key mode from that picker
lock. Start now backs up and temporarily enables `useOpenAIKey`, without writing
any native provider key, account token, email, membership, or payment response.
A nonempty saved-but-disabled OpenAI key record blocks this change, so a key the
user disabled is not silently reactivated. Both the legacy and encrypted native
secret locations are checked by presence, without decrypting their contents.

The catalog also supplies Cursor's native named-model display configuration.

only when searching. Cursor merges incoming display objects, so Start clears
and backs up the previous catalog display and locked-selection caches. Version 3
preference backups restore these fields and own-key mode exactly; versions 1 and
2 remain readable for recovery. Cursor must be fully quit before Start or Stop.

### Remaining validation boundaries

This is not exhaustive certification of every conditional native feature.
Semantic search/indexing, cloud agents, voice, video, screen recording, and
provider-defined computer tools were not enabled/tested by this fixture.
Their presence in shipped declarations alone does not establish support.

Some Letum responses repeated short phrases. A separate raw synthetic SSE
probe (text and two commit variants) did not reproduce duplication or hidden
reasoning exhaustion. Native consumer inspection found one append per delta.
A proven, separately tested OpenAI multi-choice defect was fixed: alternative
choices no longer interleave text, reasoning, tool arguments or finish markers
with choice zero. That fix is not claimed to explain the observed occasional
single-answer phrasing. Heuristic text deduplication was deliberately avoided
because it would corrupt legitimate repeated text.

## Captured follow-up findings

CodeRabbit's retained PR #16 configuration-write finding was reproduced:
concurrent Save calls and routing reads could observe truncated JSON and lose
the adapter list. Configuration writes now publish a synced, private temporary
file via replacement; a shared lock covers all readers, saves and read/modify/
write operations. A delayed connectivity probe updates only its unchanged
adapter's test metadata, preserving settings edited while the request ran.
The dashboard also merges only test metadata into the same unchanged row; a
late response cannot replace an edited/deleted row or target a newly opened editor.
Regression tests reproduced the backend failures before the fix and pass afterward,
including concurrent routing reads and failed-publication cleanup.

The repeated native GenerateImage invocation on the correctly trusted session
received HTTP 404, `application/json`, Connect error code `not_found` from the
Cursor upstream. An observer attached only to this RPC preserved response bytes
and logged no request body, credentials, image contents or arbitrary error text.
The RPC is outside the local response table and uses verified native
passthrough. This narrows the failure to the remote response; no account-plan
reason was returned and image support is not claimed.

CreatePlan revealed a local defect that the Windows normalizer alone could not
repair: its advertised parameters were wrapped as `{jsonSchema: {...}}`. The
provider received the wrapper, and normalization looked at that same wrong
level. The captured todo argument was a string containing a valid JSON array.
The follow-up unwraps this exact native container for both provider schemas and
normalization, while preserving plain schemas and custom tool formats.
The final desktop retry completed successfully at 02:03:47: Cursor recorded a
`create_plan_v2` success and wrote `readme_test_note_81745295.plan.md` with
exactly two pending todos (`read-docs` and `update-docs`). The native transcript
showed Created Plan / README Test Note. An older plan remained selected in the
side panel; that stale panel was not mistaken for the newly created file.
