## Observed model-picker boundary

The live Cursor 3.32.4 **Glass** session displayed only Auto in its model
picker. The separate **IDE** picker displayed and selected the configured
Letum model successfully. The restriction described here is therefore specific
to the observed Glass surface, not a missing adapter or a universal restriction
on model selection. A narrowly scoped state check confirmed:

- The genuine account membership was `free`; `useOpenAIKey` was absent.
- `availableDefaultModels2` contained the configured Letum model
  (`54c6d6cf3ffb1ef0`) with `defaultOn=true` and
  `namedModelSectionIndex=1`.
- Native NameTab and Agent inference requests reached the configured Letum
  provider, including while the Glass picker remained restricted.

The installed Glass workbench explains the restriction. At UTF-16 offset
`20605240`, the React picker computes its potential free-account lock from
an authenticated, settled FREE membership with `useOpenAIKey` disabled and
no active private-inference route. It refreshes membership before confirming
that lock. `WCu` at offset `13951527` confirms FREE membership only after team
membership has resolved and no team ID exists. The resulting flag is passed
as `isFreeUserModelPickerLocked` at offset `20614851`.

The model record itself is present and enabled. The same artifact's schema at
`1677174` defines model field 38 as `named_model_section_index`, and the
catalog filtering method at `9196777` accepts enabled records before applying
surface-specific and administrator restrictions. Field 38 is a section index,
not an entitlement or BYOK authorization flag.

No membership, native own-key flag, or protobuf wire value was changed to
remove this UI restriction. Cursor's account and hosted-feature restrictions
remain in force. IDE selection, Glass selection, and provider routing are
reported separately because the observed outcomes differ.

## Native GenerateImage failure

The disposable plain-blue-image test did not create an image. Only the related
records in Cursor log session `20261126T010343` were inspected; no request
bodies, authentication headers, or conversation content are retained here.

The test helper's `mac-native-20261126-fixed.log`, line 884, records a native
`POST /aiserver.v1.AiService/RunGenerateImage` with `application/proto` at
`2026-11-26 01:19:03` (local time). In that session's
`window1_wb1/exthost/anysphere.cursor-agent-host/` log, lines 814–820 record:

- Tool `GenerateImage` / `generate_image` started at `01:19:03.027`.
- It failed at `01:19:03.780`, with reported duration 756 ms,
  `toolError=true`, and `intentionalAbort=false`.
- The message was `Failed to generate image, error: Error`; the stack's
  error type was `ManagedLocalGenerateImageError: Error`.

The paired structured log records the same error at lines 965 and 967. These
records contain no underlying HTTP status, Connect error code, entitlement
reason, or provider error. They establish the failed native invocation, but
cannot distinguish a hosted-service failure from a transport failure or
attribute it to this account's plan.

Code inspection confirms this RPC is absent from local BYOK dispatch and the
relay response-rewrite table: it uses native passthrough, retaining Cursor's
authorization, request body, and upstream response. No endpoint-specific local
defect was established from these logs. No success response, account flag, or
entitlement was fabricated. GenerateImage remains a failed hosted-tool check
with an unresolved underlying cause; native WebSearch and WebFetch success
does not establish its compatibility.

### Remaining validation boundaries

This is not exhaustive certification of every conditional native feature.
Semantic search/indexing, cloud agents, voice, video, screen recording, and
provider-defined computer tools were not enabled/tested by this fixture.
Their presence in shipped declarations alone does not establish support.

Some Letum responses repeated short phrases. A separate raw synthetic SSE
probe (text and two commit variants) did not reproduce duplication or hidden
reasoning exhaustion. Native consumer inspection found one append per delta.
A proven, separately tested OpenAI multi-choice defect was fixed: alternative
choices no longer interleave text, reasoning, tool arguments or finish markers
with choice zero. That fix is not claimed to explain the observed occasional
single-answer phrasing. Heuristic text deduplication was deliberately avoided
because it would corrupt legitimate repeated text.
